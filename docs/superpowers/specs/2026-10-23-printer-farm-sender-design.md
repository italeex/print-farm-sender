# Printer Farm Sender — дизайн

Дата: 2026-10-23
Статус: утверждён в чате, дополнен требованием мультивыбора файлов

## Цель

Нативное Windows-приложение на Python, которое за минимальное время отправляет один или несколько `.gcode` файлов на выбранные 3D-принтеры Creality (K2/F008) по локальной сети. Печать после загрузки не запускается.

## Не входит в scope

- Запуск/остановка печати.
- Cloud, аккаунт Creality, авторизация.
- Прошивки, отличные от Moonraker.
- Пакетирование в `.exe` (можно добавить позже через PyInstaller).

## Требования

1. Окно Tkinter, запуск двойным кликом через `Запустить.bat` (pythonw, без консоли).
2. Список принтеров хранится в `printers.json` рядом с приложением.
3. При первом запуске, если `printers.json` отсутствует, список заполняется из самого свежего `%APPDATA%\Creality\Creality Print\*\deviceInfo.json` (все записи с непустым `address`, дедупликация по host:port, имя = `model` + последний октет IP, например `F008 100`). После этого Creality Print не используется.
4. Менеджер принтеров: добавить, удалить, переименовать, изменить IP/порт.
5. Проверка доступности каждого принтера: `GET http://host:port/server/info`, HTTP 200 = online, таймаут 1.5 с, параллельно.
6. Выбор нескольких `.gcode` файлов за один раз (`askopenfilenames`).
7. Выбор принтеров чекбоксами: вручную, «Выбрать все», «Выбрать онлайн».
8. Отправка всех выбранных файлов на все выбранные принтеры. Каждый принтер получает все файлы; принтеры работают параллельно, файлы на одном принтере — последовательно.
9. Общий трекбар: прогресс по числу завершённых принтеров (успех, ошибка или отмена — принтер считается завершённым), подпись вида `Принтеры: 3/13 · Файлы: 7/26 · 12.4 МБ/с`.
10. Для каждого принтера: свой трекбар текущего файла, статус (`ожидание`, `отправка 2/3`, `готово`, `ошибка`), скорость.
11. Отмена прерывает все незавершённые загрузки.
12. Поддержка кириллицы и пробелов в именах файлов.
13. Одноимённые файлы из разных папок в одном пакете запрещены (иначе перезапись на принтере). Показывается предупреждение до старта.

## Модель данных

`printers.json`:

```json
{
  "printers": [
    {"name": "F008 100", "host": "192.168.7.100", "port": 7125}
  ],
  "last_dir": "C:\\Users\\...\\gcode",
  "window": {"width": 1180, "height": 760}
}
```

- `name` — отображаемое имя, редактируется.
- `host` — IPv4 или hostname.
- `port` — по умолчанию `moonrakerPort`, если он > 0 в `deviceInfo.json`, иначе 7125.
- Дубликаты `host:port` при загрузке удаляются (первый выигрывает).
- Некорректный/битый JSON: приложение показывает ошибку и запускается с пустым списком, файл не перезаписывает до сохранения пользователем.

## Протокол загрузки

Moonraker:

```
POST http://{host}:{port}/server/files/upload
Content-Type: multipart/form-data
fields:
  root = gcodes
  file = <basename>, содержимое файла
```

- Успех: HTTP 201, тело `{"result": {...}}`.
- Одноимённый файл перезаписывается Moonraker (`shutil.move`).
- `requests.Session` на каждый принтер, `connect timeout = 3 c`, `read timeout = 60 c`.
- Прогресс считается обёрткой над файлом: при каждом `read()` увеличивается счётчик байт; раз в 0.2 с вычисляется скорость.
- Отмена: `threading.Event`; обёртка бросает `UploadCancelled`, поток завершает загрузку.

## Потоки и UI

- `ThreadPoolExecutor(max_workers = число выбранных принтеров)`, по одному worker на принтер.
- Внутри worker: цикл по файлам; при первой ошибке принтер помечается `ошибка`, оставшиеся файлы для него не отправляются; остальные принтеры продолжают.
- UI не трогается из потоков. Все события идут в `queue.Queue`:
  - `printer_status(host, text)`
  - `file_progress(host, file_index, file_total, bytes_done, bytes_total, speed)`
  - `file_result(host, filename, ok, message)`
  - `overall(printers_done, printers_total, files_processed, files_total, aggregate_speed)`
  - `finished(summary)`
- Главный поток опрашивает очередь каждые 100 мс через `root.after`.
- Общий трекбар — `determinate`, максимум = `len(selected_printers)`, значение = число завершённых принтеров. В подписи также счётчик обработанных файлов (`ok + failed`) из `len(files) * len(selected_printers)`.
- Скорость в подписи — сумма текущих скоростей всех принтеров.

## Макет окна

```
[Файлы: 2 выбрано] [Выбрать файлы...] [Очистить]
[Проверить связь] [Выбрать все] [Выбрать онлайн] [Отправить] [Отмена]
[==================== 7/26 ====================]  Принтеры: 3/13 · Файлы: 7/26 · 12.4 МБ/с
+---------------------------------------------------------------+
| [x] F008 100      192.168.7.100   отправка 2/2  [====   ] 8.1 МБ/с |
| [x] F008 103      192.168.7.103   готово        [========]        |
| [ ] F008 150      192.168.7.150   offline       [        ]        |
+---------------------------------------------------------------+
Лог / итог
```

- Список принтеров — прокручиваемый `Canvas` + `Frame`, в каждой строке чекбокс, имя, IP, статус, `ttk.Progressbar`, скорость.
- Offline-принтеры подсвечиваются красным статусом, но остаются выбираемыми; при отправке ошибка связи отображается в результате.
- Менеджер принтеров — отдельное `Toplevel` с таблицей и кнопками.

## Ошибки и граничные случаи

- Файл не `.gcode` / пустой / не существует — предупреждение, отправка не стартует.
- Ничего не выбрано (файлы или принтеры) — предупреждение.
- Одинаковые basename среди выбранных файлов (сравнение без учёта регистра) — предупреждение, отправка не стартует.
- HTTP 4xx/5xx — в строке принтера `ошибка HTTP <code>`, тело ответа (до 200 символов) в лог.
- Сетевая ошибка/timeout — `ошибка связи: <текст>`, остальные принтеры продолжают.
- Отмена — статусы `отменено`, общий трекбар останавливается, кнопка «Отправить» снова активна.
- Приложение не блокирует закрытие окна при активной отправке: закрытие запрашивает подтверждение и ставит `cancel`.

## Тестирование

`unittest`, без реальных принтеров:

1. `test_load_config_creates_default` — нет файла → пустой конфиг.
2. `test_seed_from_device_info` — временный `deviceInfo.json` → корректные host/port, дедупликация, пропуск пустых address.
3. `test_config_roundtrip` — сохранение/чтение, кириллица в именах.
4. `test_duplicate_basenames` — обнаружение конфликта.
5. `test_upload_multipart` — фейковый Moonraker на `127.0.0.1`, проверка полей `root=gcodes`, `file`, имени и содержимого, ответ 201.
6. `test_upload_progress_and_speed` — прогресс доходит до 100%, скорость > 0.
7. `test_upload_cancel` — медленный фейковый сервер + отмена → `UploadCancelled`.
8. `test_online_probe` — фейковый сервер отвечает 200/таймаут.

## Критерии готовности

- Импорт 25 принтеров из текущего `deviceInfo.json` при первом запуске.
- Отправка 2 файлов на 3 принтера: 6 одновременных задач (по 3 принтера), корректные прогресс/скорость/итоги.
- Отмена во время отправки оставляет приложение работоспособным.
- Тесты проходят командой `python -m unittest discover -s tests -v`.
- Запуск `Запустить.bat` открывает окно без консоли.
