# Printer Farm Dashboard — дизайн

Дата: 2026-10-26
Статус: на утверждении
Предшественник: `2026-10-23-printer-farm-sender-design.md` (рассыльщик v1)

## Цель

Превратить рассыльщик gcode-файлов в полноценный дашборд фермы принтеров Creality K2 Plus: карточки принтеров с живым статусом, превью печатаемой модели, прогрессом, температурой, ошибками с расшифровкой кодов Creality, кнопкой Mainsail и управлением печатью (пауза/продолжить/отмена). Отправка файлов на выбранные принтеры сохраняется и становится частью дашборда.

## Зачем

Сейчас ферма из 25 принтеров видна только как список строк: статус «online/offline», без того, что печатается и как идёт печать. Оператору приходится открывать Mainsail каждого принтера. Дашборд должен дать ответ «что происходит на ферме» с одного экрана и позволить быстро отправить следующий файл.

## Что вошло в договорённости с пользователем

- Камеры **не делаем**: K2 Plus не отдаёт кадры (WebRTC DTLS не поднимается ни в aiortc, ни в Chrome; проверено на живом принтере). В карточке — превью модели из gcode, не камера.
- Интерфейс — **локальный веб-дашборд в браузере**, тёмная тема, адаптивная сетка карточек. Никаких новых Python-зависимостей: только стандартная библиотека и уже используемый `requests`.
- Превью — встроенные в gcode PNG-миниатюры 300×300 (проверено: есть у всех файлов на принтере).
- Mainsail — ссылка `http://<host>:<mainsail_port>`, по умолчанию порт 4408.
- Ошибки — парсить коды Creality (таблица K2 Plus с префиксами `AC/AL/FR/FS/FB/FO/TE/TR/TC/TF/XS/XD` и числовые коды), показывать понятную формулировку, код, подсказку и ссылку на вики Creality; fallback — текст Klipper.
- Управление печатью — кнопки паузы, продолжения и отмены печати прямо в карточке.

## Не входит в scope

- Камеры и видеопоток (осознанно, см. выше; интерфейс оставляет место под будущее встраивание).
- Запуск печати после загрузки (upload-only остаётся).
- CFS/филамент-менеджмент, калибровки, прошивки, Creality Cloud.
- Авторизация и удалённый доступ: сервер слушает только `127.0.0.1`.
- Светлая тема, локализации кроме русской.
- Мобильное приложение; адаптивность ограничена узким окном браузера.

## Ограничения

- Python 3.13.7, Windows, только stdlib + `requests`. Никаких Flask/FastAPI/JS-сборщиков/CDN.
- Все пользовательские тексты — на русском.
- Тесты никогда не ходят к реальным принтерам: только fake Moonraker на `127.0.0.1` с эфемерным портом.
- `printers.json` — UTF-8, `ensure_ascii=False`, атомарная запись.
- Код без комментариев.
- Сервер работает в фоне под `pythonw`; никаких висящих процессов после закрытия дашборда дольше заданного idle-таймаута.
- Работа только внутри каталога проекта; git-коммиты локальные.

## Рассмотренные подходы

1. **Тёмный Tkinter** — минимум изменений, но «красиво» в Tkinter недостижимо: нет скруглений, теней, адаптивной сетки, нормальной типографики.
2. **Локальный веб-дашборд (выбран)** — stdlib HTTP-сервер + HTML/CSS/JS. Даёт современный вид и адаптивность без новых зависимостей; цена — браузерная вкладка вместо нативного окна и собственный файловый браузер вместо системного диалога.
3. **pywebview-оболочка** — красиво и нативно, но добавляет зависимость и движок WebView2; отклонено как избыточное.

Решение: вариант 2.

## Модель данных

`Printer` получает поле `mainsail_port: int = 4408`. `from_dict` подставляет 4408 при отсутствии/мусоре; `to_dict` пишет его всегда. Старые `printers.json` читаются без миграции. `AppConfig.window` сохраняется для обратной совместимости, но веб-дашбордом игнорируется; добавляется `refresh_seconds: int = 5` (необязательный, clamp 2–30).

`printers.json`:

```json
{
  "printers": [
    {"name": "F008 100", "host": "192.168.7.100", "port": 7125, "mainsail_port": 4408}
  ],
  "last_dir": "C:\\\\...\\\\gcode",
  "window": {"width": 1180, "height": 760},
  "refresh_seconds": 5
}
```

## Модель состояния принтера

Каждый цикл опроса собирает `PrinterView`:

- `key`, `name`, `host`, `mainsail_url`
- `online` (последний опрос успешен), `last_seen` (unix time)
- `state`: `printing | paused | idle | error | offline`
- `file`: имя текущего/последнего файла
- `progress`: 0..1
- `layers`: `{current, total}` из `virtual_sdcard.layer/layer_count`
- `eta_seconds`: из `virtual_sdcard.cur_print_data.end_time` минус now (если валидно)
- `temps`: `{nozzle, bed}`; `filament_type`
- `thumb_version` (для URL превью); `thumbnail` отдаётся отдельным эндпоинтом
- `error`: `{code, label, hint, detail, help_url}` или null

Маппинг состояний:

| Moonraker | UI |
|---|---|
| `printing` | `printing` — «Печатает» |
| `paused` | `paused` — «Пауза» |
| `standby` | `idle` — «Свободен» |
| `complete`, `cancelled` | `idle` — «Свободен»; файл показывается как «последняя печать» (приглушённо) |
| `error` | `error` — «Ошибка» |
| `/printer/info.state` = `error`/`shutdown` | `error`, даже если `print_stats` говорит иное |
| запрос не удался | `offline` — «Не в сети», карточка приглушена |

Офлайн-бэкофф: успешный опрос — интервал `refresh_seconds`; первая ошибка — 10 с, далее 20, 30, 60 с максимум; успех сбрасывает. Таймаут запроса 2.5 с. Параллельность — `ThreadPoolExecutor(max_workers=16)`, один воркер на принтер за цикл, отдельный `requests.Session` на поток.

Порядок опроса и различение отказов:

1. `GET /printer/info` — определяет доступность Moonraker и состояние Klipper (`state`, `state_message`).
2. `GET /printer/objects/query` (`print_stats`, `virtual_sdcard`, `extruder`, `heater_bed`, `display_status`).

- Сетевой отказ/таймаут на шаге 1 → `offline` (принтер недоступен).
- Шаг 1 успешен, `state` = `error`/`shutdown` → `error`, даже если объекты не читаются; `detail` из `state_message` и klippy.log.
- Шаг 1 успешен, шаг 2 упал (Klipper ещё поднимается, 503 и т.п.) → `error` с подписью «Klipper не отвечает», а не `offline`; сохраняется `online=true`.
- HTTP 4xx на шаге 2 (несовместимая версия) → `error` с текстом ответа, принтер остаётся online.

Так «принтер выключен» и «Klipper упал» не смешиваются в одну серую карточку.

## Ошибки Creality

Источники (в порядке приоритета):

1. `print_stats.message` — если непустое.
2. `/printer/info.state_message` — состояние Klipper.
3. При `state=error`/`shutdown`: хвост `klippy.log` (`GET /server/files/logs/klippy.log`, `Range: bytes=-65536`), последняя JSON-строка вида `!! {"code":"key2564","msg":"..."}`.

Парсер:

- нормализует строку, срезает `!!`, пробелы, префикс `key`;
- ищет код формата `AC0101`, `TE2509`, `XS2060`, `XD2571` или `Key: 2564`;
- ищет код в таблице `CREALITY_ERRORS` (полный код → затем числовая часть);
- если кода нет — keyword-fallback по тексту Klipper (`thermistor`, `lost communication with mcu`, `not heating`, `move out of range`, `filament runout`, `timer too close`, `endstop`, `shutdown` и т.д.);
- неизвестное — `label="Ошибка принтера"`, `detail` = сырой текст (до 300 символов, первая строка).

Карточка показывает `label` и код; клик открывает модалку с `detail`, `hint` и ссылкой `help_url` на `https://wiki.creality.com/en/k2-flagship-series/k2-plus/error-code-summary`. В таблицу войдут коды K2 Plus из официальной вики (AI-детекция, CFS, hotend, tool kit, system), плюс частые числовые K1/Klipper-коды (термистор, нагрев, MCU, концевые датчики, G-code). Ошибка сохраняется, пока состояние не станет `ready`/`printing` — чтобы оператор увидел причину, даже если принтер уже перезапустился.

## Превью модели

- Для печатающего/последнего файла: `GET /server/files/gcodes/<quoted path>` с `Range: bytes=0-262143`; парсинг блоков `; thumbnail begin WxH N` … `; thumbnail end`; выбор блока с максимальной площадью; base64 → PNG; проверка сигнатуры PNG. Кэш в памяти по ключу `(host, filename, modified, size)`, LRU на 64 записи. Отдача через `GET /api/thumb/<printer_key>?v=<thumb_version>` с `ETag`/`Cache-Control: immutable`.
- Для локальных файлов в файловом браузере: чтение первых 256 КБ с диска и тот же парсер; встроенное превью в карточке выбранного файла.
- Нет миниатюры → плейсхолдер «Превью нет».
- Загрузка превью не блокирует опрос: отдельный пул (4 воркера), приоритет печатающим.

## Управление печатью

Эндпоинты Moonraker: `POST /printer/print/pause`, `/printer/print/resume`, `/printer/print/cancel`. Сервер вызывает их после проверки `online` и текущего состояния; ответ 200 → тост и принудительный опрос; 4xx/5xx → тост с текстом ошибки Moonraker. Отмена печати — только после подтверждения в модалке. Кнопки: «Пауза» при `printing`, «Продолжить» при `paused`, «Отменить» при `printing|paused`, иначе скрыты. Это единственные управляющие вызовы; загрузка/печать не смешиваются.

## HTTP API

Сервер: `ThreadingHTTPServer`, bind `127.0.0.1`, порт по умолчанию 8765 (при занятости — 8766…8775). Только локально, без CORS для внешних источников. Статика из `web/` с корректными MIME и no-cache для HTML/JS/CSS.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | `index.html` |
| GET | `/api/state` | полный снимок: `printers[]`, `summary`, `job`, `config` |
| GET | `/api/thumb/<key>?v=` | PNG-превью печати |
| GET | `/api/files/thumb?path=` | PNG-превью локального файла |
| GET | `/api/fs?path=` | список дисков/папок/`.gcode`; `{path,parent,entries[]}` |
| GET | `/api/journal?since=` | последние события (in-memory, до 200) |
| POST | `/api/send` | `{printers:[key], files:[path]}` → запуск BatchSender |
| POST | `/api/job/cancel` | отмена отправки |
| POST | `/api/print/<key>/pause\|resume\|cancel` | управление печатью |
| GET/POST | `/api/printers` | список/добавление |
| PUT/DELETE | `/api/printers/<key>` | изменение/удаление |
| POST | `/api/heartbeat` | продление жизни сервера |
| POST | `/api/shutdown` | корректная остановка |

Ошибки API: JSON `{error: "..."}` с 4xx/5xx и русским текстом. Все пути файлов валидируются: только существующие `.gcode`, без дублей basenames (переиспользуется `validate_files`).

Файловый браузер: диски через `os.listdrives()` (fallback — `GetLogicalDrives`), папки и `.gcode`-файлы, сортировка «папки → файлы», размер и дата; навигация вверх/по хлебным крошкам; запоминание `last_dir`; ошибки доступа показываются тостом, а не падением.

Job-менеджер: один активный job; состояние `{running, printers_total, printers_done, files_total, files_processed, aggregate_speed, per_printer{key:{status,file,progress,speed}}, finished, ok, failed, cancelled}`. События `BatchSender` складываются в это состояние и в журнал; фронтенд опрашивает `/api/state` каждые 2 с (во время job — 1 с). Отмена — как в v1 (не рвёт уже отправляемый POST, останавливает очередь).

## Интерфейс

Тёмная тема (фон #0a0c11, карточки #141821, акцент #5b8cff). Без внешних шрифтов и CDN — системный стек Segoe UI + Cascadia Mono для цифр.

Структура страницы:

1. **Шапка**: логотип, название, число принтеров и интервал обновления, индикатор сервера, кнопки «Обновить», «Принтеры».
2. **Сводка**: плитки «Печатают / Пауза / Свободны / Ошибки / Не в сети» и «ближайший финиш».
3. **Тулбар**: поиск (имя, IP, файл), фильтры-чипы, «Выбрать онлайн», «Снять выбор», «Отправить» (primary), «Отмена».
4. **Лоток файлов**: выбранные файлы, их количество и оценка числа отправок; кнопка «Выбрать файлы…» открывает файловый браузер.
5. **Сетка карточек** `repeat(auto-fill, minmax(290px, 1fr))`.
6. **Журнал** — выдвижная панель снизу: последние события и ошибки.
7. **Модалки**: файловый браузер, менеджер принтеров, детали ошибки, подтверждение отмены печати/удаления принтера.

Карточка: чекбокс выбора, имя, `host:port`, статус-пилюля, превью 300×300 (или плейсхолдер), имя файла (2 строки, ellipsis), прогресс-бар + %, ETA, слой `N/M`, температуры сопла/стола, тип филамента, кнопки «Mainsail», «Пауза/Продолжить», «Отменить печать» (в меню «•••»), тонкая полоса прогресса отправки текущего job.

Поведение:

- Карточка `complete` показывает последний файл и превью приглушённо с подписью «последняя печать»; статус — «Свободен».
- Ошибка — красная плашка под именем файла: `label` + код; клик → детали.
- Офлайн — карточка приглушена, кнопки управления недоступны, показывается «последний ответ N мин назад».
- Выбор: чекбокс, «Выбрать онлайн», «Все», «Снять»; счётчик выбранных виден на кнопке отправки.
- Отправка блокирует повторный старт, но не мешает просмотру; отмена доступна.
- Тост-уведомления: успех/ошибка, автоскрытие 5 с; журнал хранит историю.
- Клавиатура: `/` — фокус в поиск, `Esc` — закрыть модалку, `Ctrl+Enter` — отправить.
- Переключатель «подробно/компактно» (localStorage), при компактном превью уменьшается до 96 px и скрывается часть метаданных.
- Пустые состояния: «Принтеров нет — добавьте», «Ничего не найдено», «Файлы не выбраны».

Доступность: контраст текста ≥ 4.5:1, видимый focus-ring, подписи у иконочных кнопок, `aria-live` для тостов, статусы не только цветом, но и текстом.

## Жизненный цикл сервера

- `Запустить.bat` запускает `pythonw farm_server.py`; сервер поднимается, печатает URL в `farm.log`, открывает браузер (`webbrowser.open`), стартует поллер.
- `POST /api/shutdown` останавливает поллер, job (с отменой), сервер и завершает процесс.
- Heartbeat: фронтенд шлёт `POST /api/heartbeat` каждые 10 с; если 10 минут нет heartbeat и нет активного job — сервер завершается сам (закрытая вкладка не оставляет процесс). Активный job продлевает жизнь независимо от heartbeat.
- Порт занят — следующий из диапазона; фактический порт пишется в `farm.log` и в консоль (если есть).
- Логи: `farm.log`, `RotatingFileHandler(1 МБ, 3 файла)`, UTF-8; в веб — журнал последних 200 событий.

## Тестирование

Никаких реальных принтеров. Fake Moonraker расширяется: статус, `/printer/info`, `/printer/print/*`, klippy.log, Range-выдача gcode с миниатюрой, ошибки.

- `test_errors.py`: коды Creality (`TE2509`, `XS2060`, `FR2839`, `AC0101`), числовые (`2564`), `Key: 2509`, неизвестный код, пустое сообщение, keyword-fallback, JSON из klippy.log, мусорный JSON.
- `test_thumbs.py`: разбор 96/300, выбор максимального, битый base64, отсутствие миниатюр, локальный файл и HTTP Range.
- `test_monitor.py`: маппинг состояний (включая `complete`/`cancelled`), ETA из `end_time`, слои, офлайн-бэкофф, восстановление после офлайна, ошибка Klipper при `ready`, троттлинг.
- `test_server.py`: `/api/state`, `/api/thumb`, `/api/fs`, добавление/изменение/удаление принтера, pause/resume/cancel (проверка вызова Moonraker), `/api/send` с fake BatchSender, cancel job, heartbeat/shutdown, 404 и битые параметры.
- `test_farm_core.py`: существующие 23 теста + `mainsail_port` (чтение старого конфига, запись нового), обратная совместимость.
- Frontend: без unit-тестов; проверка вручную по чек-листу (открытие, фильтры, отправка на fake-ферму, пауза, ошибки, адаптивность при 1280/1920, компактный режим, закрытие вкладки).
- Проверка кодировки: кириллические имена файлов и принтеров в JSON, HTML и логах.

## Риски и решения

- **Браузерная вкладка вместо окна** — принято пользователем; запуск из `.bat`, автооткрытие.
- **Пропадающие принтеры** — 10 из 25 сейчас не отвечают; бэкофф и «не в сети» вместо зависания UI.
- **Нагрузка опроса** — 2 запроса × 15 принтеров / 5 с ≈ 6 rps, таймаут 2.5 с, 16 воркеров; превью отдельным пулом.
- **Размер JS без фреймворка** — модульный `app.js` (~600–900 строк), чистые функции для форматирования, никакой сборки.
- **Таблица ошибок устареет** — данные статичны, есть ссылка на вики; неизвестное показывается как есть.
- **Файловый браузер на Windows** — аккуратная обработка `PermissionError`, длинных путей, сетевых дисков; только чтение.
- **Потеря Tkinter-версии** — код в истории git; README фиксирует переход.

## Проверка после реализации

1. `python -m unittest discover -s tests -v` — всё зелёное, реальные принтеры не задействованы.
2. Запуск `Запустить.bat`: браузер открывается, 25 карточек, статусы совпадают с Mainsail.
3. Отправка 1 файла на 2 принтера: прогресс, «успешно 2, ошибок 0», файл появился в Mainsail.
4. Пауза/продолжение/отмена на печатающем принтере — состояние и тосты корректны.
5. Ошибка: имитация через fake Moonraker — код, описание, ссылка.
6. Закрытие вкладки: сервер завершается через idle-таймаут; `farm.log` без трейсбеков.

## Уточнения после проверки строителем

- **Единственный экземпляр**: перед стартом проверяем `GET http://127.0.0.1:<port>/api/state`; если отвечает — открываем существующий дашборд и завершаемся; иначе занимаем порт 8765…8775.
- **Согласованность состояния**: один поток-поллер пишет неизменяемый снимок под `threading.Lock`; обработчики API копируют снимок и не ходят в сеть принтеров напрямую (кроме control-эндпоинтов, которые выполняются в фоновом исполнителе с таймаутом).
- **Обновление DOM без перерисовки**: карточки создаются один раз по ключу принтера и обновляются точечно (текст, ширины, классы), поэтому не сбрасываются фокус, hover, выделение и скролл. `<img>` получает новый `src` только при смене `thumb_version`. Полный ререндер — только при изменении состава принтеров.
- **Локальная защита API**: bind только `127.0.0.1`; POST/PUT/DELETE требуют `Content-Type: application/json`; запросы с заголовком `Origin`, отличным от `http://127.0.0.1:<port>`/`http://localhost:<port>`, отклоняются 403. Ответы с `X-Content-Type-Options: nosniff` и `Cache-Control: no-store` для API.
- **klippy.log**: `Range: bytes=-65536`; если сервер не поддерживает Range (нет 206), допускается полная загрузка лога с ограничением 2 МБ и парсингом хвоста. При любой ошибке — молчаливый fallback на текст состояния.
- **Где реально встречаются коды Creality**: коды вида `TE2509`/`XS2060` приходят в тексте состояния/Klipper-лога (`key2564`) не всегда; если код не найден, показываем текстовую расшифровку по ключевым словам. Не используем недокументированный порт 9999. Таблица кодов расширяема, ссылка на вики — в модалке.
- **Изменение принтера**: при редактировании `host`/`port` меняется `key`; монитор сбрасывает для него кэш статуса и превью, выбор в UI переезжает на новый ключ, job с этим принтером не затрагивается.
- **CSRF-риск** закрыт проверкой Origin и JSON-типом; токен не нужен, сервер локальный.
- **Проверка паузы/продолжения** на живой ферме — только вручную, на принтере, который печатает; автоматические тесты используют fake Moonraker.
- **Форматирование времени**: ETA считается только при валидном `end_time` и состоянии `printing`; для `paused` показывается «на паузе», для `idle` — «—».
