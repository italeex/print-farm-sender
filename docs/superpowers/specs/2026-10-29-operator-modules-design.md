# Дашборд оператора: вкладки, файлы, смены, ОТК

Дата: 2026-10-29. Статус: на согласовании.

## Зачем

Дашборд вырос из мониторинга в рабочий инструмент оператора фермы из 13 принтеров.
Сейчас всё живёт в одной странице: карточки, девять модальных окон, кнопки в шапке.
Оператору нужно за смену ответить на четыре вопроса:

1. Что происходит с фермой прямо сейчас?
2. Какие файлы лежат на принтерах и не устарели ли они?
3. Что запускать дальше, чтобы закрыть план?
4. Что отпечаталось за сутки и что нести на ОТК?

Ответы должны быть на своих вкладках, без перегруза.

## Что уже есть

- 13 принтеров, опрос каждые 2 секунды, состояния `printing/paused/idle/error/offline`.
- Загрузка gcode на принтеры (только загрузка, без запуска печати).
- Пауза, продолжение, отмена; массовые действия по выбранным принтерам.
- История событий в SQLite, факт по деталям, план на день/неделю, календарь месяца.
- Факт «готово + в процессе» вида `0 (+16)`.
- Детали текущей печати определяются по `EXCLUDE_OBJECT_DEFINE` в gcode.
- `part_key`: обозначение без `МВСЛ`/`МФСЛ`, пробелов, `_`, `.stl`, регистра.

## Ограничения и не-цели

Ограничения:

- Python stdlib + `requests`, без новых зависимостей.
- Тесты не ходят на реальные принтеры; только fake Moonraker на `127.0.0.1`.
- Сервер слушает только `127.0.0.1`.
- Запуск печати остаётся ручным. Приложение по-прежнему не вызывает endpoint старта:
  планировщик раскладывает файлы и говорит, что и где нажать. Автозапуск — отдельное
  решение, требующее явного согласия.
- Все операции с файлами на принтерах — только внутри папки фермы.
- Удаление файлов необратимо: всегда подтверждение со списком.

Не-цели первой версии:

- Авторизация и несколько операторов.
- Автозапуск печати.
- Управление слайсером и переслайсинг.
- Учёт филамента и склад.
- Мобильная версия.

## Подходы

### A. Структура интерфейса

1. **Вкладки в одной странице с hash-маршрутами** (`#/overview`, `#/files`, `#/plan`,
   `#/shift`, `#/printers`, `#/log`). Выбрано.
2. Отдельные HTML-страницы. Больше дублирования, теряется живое обновление,
   переходы перезагружают состояние.
3. Оставить модалки и добавить ещё. Не решает перегрузку, растёт число слоёв.

Выбор: вкладки, потому что существующий код уже разделён на функции рендера,
а модалки остаются для деталей (история принтера, ошибка, подтверждение).

### B. Папка фермы на принтере

Проверено на свободном принтере F008 103: прошивка принимает загрузку в подкаталог
(`POST /server/files/upload` с `path=FARM`), читает каталог
(`GET /server/files/directory?path=gcodes/FARM`) и удаляет файл
(`DELETE /server/files/gcodes/FARM/<имя>`). Пробный файл 1 КБ создан и удалён.
Поэтому папка `FARM` — основной режим, а не гипотеза.

Папка `FARM` создана на всех 13 принтерах с файлом `папка-фермы.txt` внутри.
Так оператор видит её с экрана принтера. Файл служебный, приложение его не трогает
и в реестр наших деталей не включает. После переименования на принтерах осталась
пустая папка `Серия`: Moonraker не умеет удалять каталоги, её можно убрать с экрана
принтера вручную.

1. **Подкаталог `FARM` в `gcodes`.** Выбрано и проверено.
2. Префикс имени `FARM_` в корне — резерв, если другой принтер ответит отказом.
3. Только локальный реестр без изменений на принтере. Не даёт удалять и обновлять.

Режим хранится по принтеру в базе и применяется прозрачно: список, удаление и сверка
«файл совпал» работают с логическим именем (`N<N>.gcode`), физический путь
строится по режиму. Повторная попытка вернуться в папку — один раз при старте сервера
и по кнопке «Переключить в папку»; без этого смешанный режим не превращается в
постоянные ошибки.

### C. Планировщик смены

1. **Жадное назначение по приоритету** (выбрано): сегодняшние позиции, затем неделя;
   внутри — больший остаток и более длинная печать вперёд. Просто объяснить оператору.
2. Глобальная оптимизация (ILP/перебор). Лучше по времени, но непредсказуема
   для оператора и тяжела без зависимостей.
3. Ручная очередь. Полный контроль, но именно ручной счёт мы убираем.

Выбор: жадный алгоритм. Его результат можно объяснить словами «почему этот принтер
получил эту деталь», а пересчёт занимает миллисекунды.

### D. Версия файла

1. **Размер файла** как признак версии, время изменения — справочно. Выбрано.
2. SHA-256. Точнее, но принтер не отдаёт хэш, сравнивать не с чем; хэширование
   60–90 МБ на каждую проверку бессмысленно.
3. Ручная отметка «актуально». Дёшево, но оператор забудет.

Выбор: размер. Совпал размер с эталоном — `актуален`; другой размер — `устарел`;
файла нет — `нет`. Время изменения показывается, но не влияет на статус.

## Дизайн

### 1. Навигация

Шапка: название фермы, счётчик проблем, вкладки, кнопка «Обновить».
Вкладки:

| Вкладка | Содержимое |
|---|---|
| **Обзор** | Сводка состояний, карточки принтеров, блок «Запустить сейчас», блок «ОТК за смену» |
| **Файлы** | Каталог деталей, номера, матрица «деталь × принтер», массовые операции |
| **План** | Календарь месяца, день/неделя, полоса выполнения, импорт |
| **Смена** | План смены 09:00–18:00, очередь по принтерам, разложение файлов |
| **Принтеры** | Список, добавление, переименование, сканирование сети |
| **Журнал** | События фермы |

Маршрут в hash, прямые ссылки работают. Модалки истории, ошибки и подтверждения
остаются. Окно плана переезжает из модалки во вкладку; кнопка «План» в шапке
становится ссылкой на вкладку.

### 2. Обзор

- Пять плиток: печатают, пауза, свободны, ошибки, не в сети. Клик фильтрует карточки.
- Карточки принтеров без изменений, плюс кнопка «Камера» и меню.
- Блок **«Запустить сейчас»**: до трёх задач, которые дают максимальный прогресс
  плана на свободных принтерах. Строка: номер, позиция, остаток, оценка времени,
  принтер, статус файла. Кнопки: «Разложить файлы» и «Открыть смену».
- Блок **«План на сегодня»**: полоса и цифры `готово + в печати из плана`.
- Блок **«ОТК»**: за период по умолчанию, кнопка «Список ОТК».

### 3. Полоса плана

Двухсегментная полоса: зелёный — завершено, синий — в печати, серый — остаток.
Подпись: `101 + 240 из 1225 · 34% + 20%`. Проценты считаются от плана, второй
процент — доля в печати. Если план 0 — полоса пустая и подпись `план не задан`.
Полоса есть на Обзоре, на вкладке План и в плашке рекомендаций.

### 4. Файлы

Каталог деталей — новая таблица `parts_catalog`:

- `part_key` — ключ сопоставления с планом и историей;
- `number` — короткий номер, целое больше нуля, уникальное, задаёт оператор или
  система выдаёт следующий свободный;
- `code`, `name` — обозначение и название из плана/файла;
- `file_path`, `file_size`, `file_mtime` — локальный эталон;
- `updated_at`.

Правила:

- Показ везде: `Номер N`, затем короткое имя. Полное обозначение — в подсказке.
- Имя файла на принтере фиксировано: `N<N>.gcode`, например `N7.gcode`.
  Обновление перезаписывает тот же файл, старых копий не остаётся.
- Загрузка идёт в папку фермы; вне её приложение ничего не читает и не удаляет.
- Реестр `file_registry` хранит снимок папки по каждому принтеру: имя, размер,
  время изменения, когда видели.
- Статус ячейки: `актуален`, `устарел`, `нет`, `печатается`. Считается на чтении.

Матрица «деталь × принтер»:

- строки — детали каталога, столбцы — принтеры; ячейка — статус;
- фильтры: «только проблемы», поиск по номеру/обозначению;
- выбор строк и столбцов, затем действия: **Разложить**, **Обновить**,
  **Удалить с выбранных**, **Удалить везде**;
- перед действием — сводка: сколько файлов, на каких принтерах, сколько МБ;
- результат по каждому принтеру: успех/ошибка, без остановки на первой ошибке;
- «Обновить список» перечитывает папки принтеров, не чаще одного раза в 15 секунд
  на принтер.

Импорт эталона: «Эталон…» у детали открывает файловый браузер, по умолчанию берётся
имя файла как обозначение, ключ считается тем же `part_key`.

Пополнение каталога: при чтении каталога в него добавляются все `part_key` из плана
и истории. Номер выдаётся автоматически — следующий свободный; оператор может
изменить его на любой положительный целый. Деталь без эталона видна, но в
планирование не попадает, пока файл не задан.

Защита текущей печати: если на принтере печатается или стоит на паузе файл, который
действие собирается перезаписать или удалить, принтер пропускается с явной ошибкой
в результате. Чужую печать приложение не трогает.

### 5. Планировщик смены

Окно запусков: 09:00–18:00 по локальному времени. Печать может идти ночью.
Вне окна новые запуски не предлагаются.

Входные данные:

- остаток по плану на дату: `target − actual − in_progress` (в процессе — только сегодня);
- состояние принтеров и время освобождения: свободен — сейчас; печатает — `finish_at`;
  пауза без ETA, ошибка, offline — недоступен до конца смены;
- каталог: есть ли эталон и файл на принтере;
- оценка длительности: `;TIME:` из локального gcode, иначе `estimated_time` Moonraker,
  иначе медиана завершённых печатей этой детали, иначе 4 часа с пометкой «оценка».

Алгоритм:

1. Кандидаты — позиции с остатком > 0 и доступным эталоном. Сначала план на дату,
   затем остаток недели.
2. Сортировка: дата, остаток по убыванию, длительность по убыванию.
3. Для каждой копии: принтер с самым ранним временем освобождения, у которого файл
   актуален или его можно загрузить; старт не позже 18:00.
4. Печать может закончиться после 18:00 — это нормально; следующий запуск на этом
   принтере будет завтра.
5. Нераспределённое показывается с причиной: нет файла, нет свободных принтеров,
   смена закрыта.

Экран смены:

- дата, окно 09:00–18:00, итог «план / готово / в печати / осталось»;
- таблица по принтерам: очередь, старт, финиш, номер, количество, статус файла;
- отдельная таблица «Не влезло» с причинами;
- кнопки «Разложить файлы», «Утвердить смену», «Пересчитать»;
- после утверждения задачи хранятся в `schedule_tasks`, статусы обновляются по
  событиям монитора: совпал файл — `printing`, завершилось — `done`.

Одна задача — одна копия: в очереди принтера каждая строка это один запуск со своим
стартом и финишем. Ручные правки оператора (исключить, переставить принтер, сдвинуть)
живут на клиенте до «Утвердить смену»; `GET /api/schedule` ничего не пишет.
Пересчёт сохраняет ручные правки до конца смены.

Принтер на паузе считается недоступным до продолжения: оператор должен снять паузу,
только после этого планировщик снова его учитывает. Оценка финиша у паузы не
используется.

Следующий рабочий день — ближайший день с позициями плана; если плана нет вообще,
ближайший будний день.

### 6. ОТК

Отчёт за период по умолчанию: вчера 09:00 — сегодня 09:00. Выбор даты — календарь.
Дата в отчёте означает смену, закончившуюся в этот день: границы 09:00 предыдущего
дня — 09:00 выбранного. Источник — завершённые события с `parts_json`, отменённые
и ошибки не входят.

Содержимое:

- таблица: позиция (`Номер N` и название) и количество;
- итог: позиций и деталей;
- кнопки «Копировать», «CSV», «Печать»;
- пустое состояние «за период ничего не завершено».

Группировка по `part_key`, количество суммируется. Один и тот же файл, напечатанный
на трёх принтерах, — одна строка с количеством и списком принтеров.

### 7. API

Новые маршруты (все только `127.0.0.1`, ошибки по-русски):

- `GET /api/catalog` — каталог и статусы файлов по принтерам.
- `POST /api/catalog` — задать номер и/или эталон.
- `POST /api/files/sync` — перечитать папки фермы.
- `POST /api/files/upload` — разложить/обновить файлы по выбранным принтерам.
- `POST /api/files/delete` — удалить файлы фермы по выбранным принтерам.
- `GET /api/schedule?date=YYYY-MM-DD` — расчёт смены.
- `POST /api/schedule/apply` — утвердить смену.
- `GET /api/qc?date=YYYY-MM-DD` — список ОТК.
- `GET /api/qc.csv?date=YYYY-MM-DD` — то же в CSV.

Существующие `/api/state`, `/api/plan`, `/api/plan/calendar`, `/api/plan/import`,
`/api/history/*`, `/api/send`, `/api/print/*` остаются.

### 8. Данные

```sql
CREATE TABLE parts_catalog (
  part_key TEXT PRIMARY KEY,
  number INTEGER,
  code TEXT,
  name TEXT,
  file_path TEXT,
  file_size INTEGER,
  file_mtime REAL,
  updated_at REAL
);
CREATE UNIQUE INDEX parts_catalog_number ON parts_catalog(number) WHERE number IS NOT NULL;

CREATE TABLE file_registry (
  printer_key TEXT NOT NULL,
  name TEXT NOT NULL,
  size INTEGER NOT NULL,
  modified REAL NOT NULL,
  seen_at REAL NOT NULL,
  PRIMARY KEY (printer_key, name)
);

CREATE TABLE printer_files (
  printer_key TEXT PRIMARY KEY,
  mode TEXT NOT NULL DEFAULT 'folder',
  checked_at REAL
);

CREATE TABLE schedule_tasks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,
  printer_key TEXT NOT NULL,
  part_key TEXT NOT NULL,
  number INTEGER,
  file_name TEXT,
  planned_start REAL,
  state TEXT NOT NULL DEFAULT 'planned',
  manual INTEGER NOT NULL DEFAULT 0,
  created_at REAL NOT NULL
);
```

Смена и окно запусков — в `printers.json` (`shift_start`, `shift_end`), по умолчанию
`09:00`/`18:00`. Новые таблицы создаются в существующей `farm_history.db`.

### 9. Ошибки и пустые состояния

- Принтер недоступен при работе с файлами — строка с ошибкой, остальные продолжают.
- Папка фермы не создана — «файлов нет», а не ошибка.
- Нет эталона — «эталон не задан», действие «Разложить» недоступно.
- Нет плана — планировщик пуст с подсказкой «импортируйте план».
- Смена закрыта — расчёт показывает следующий рабочий день, запуск не предлагается.

### 10. Проверка

- Модульные тесты истории: каталог, реестр, статусы, ОТК, смена.
- Fake Moonraker: список папки, загрузка в `FARM`, удаление, отказ папки и переход
  в режим префикса, ошибка одного принтера.
- Тесты планировщика: окно 09–18, ночная печать, занятый/сломанный принтер,
  нехватка файлов, пересчёт, ручная правка.
- UI: `node --check`, проверка id/селекторов, отсутствие `innerHTML`.
- Полный прогон, ревью, версия.

## Решения, принятые мной

- Вкладки на hash-маршрутах, без фреймворка.
- Папка `FARM`; fallback на префикс `FARM_` по факту отказа прошивки.
- Версия файла — по размеру.
- Жадный планировщик с объяснимыми правилами.
- Имя файла на принтере — `N<N>.gcode`.
- ОТК по умолчанию за вчера 09:00 — сегодня 09:00.
- План остаётся на вкладке, модалка плана убирается.
- Запуск печати — вручную.
- Каталог сам пополняется из плана и истории; номер выдаётся автоматически.
- Номер детали — целое, отображается как «Номер N».
- Печатающий принтер пропускается при перезаписи и удалении его текущего файла.
- `GET /api/schedule` не имеет побочных эффектов; правки живут до утверждения.
- Одна задача — одна копия.
- Пауза делает принтер недоступным, пока оператор не продолжит печать.
- Следующий рабочий день — ближайший день с планом, иначе ближайший будний.
- Список ОТК — только позиция и количество.

## Ответы пользователя

1. Пробная запись и удаление файла на свободном принтере разрешены. Проверено:
   папка и удаление работают.
2. Нумерация простая: «Номер 1», «Номер 2», дальше по порядку.
3. ОТК: только позиция и количество.
